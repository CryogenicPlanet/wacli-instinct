# Instinct read bridge

`wacli-instinct` runs one supervised `wacli sync --follow --events --disable-send-delegate` process and reconciles its local `wacli.db` into a private, durable outbox. The new flag prevents follow mode from creating wacli's same-UID send/mark-read delegate socket. This repository supplies the worker and an HTTP ingest contract. It does **not** supply or assert an existing Instinct endpoint, host, encrypted volume, paired WhatsApp account, verified group JID, classifier, or alert destination. Those must be connected and verified for a live deployment.

## Ingest contract

Configure a **first-party internal HTTPS** endpoint in `INSTINCT_INGEST_URL` and a bearer token in a worker-readable 0400/0600 file at `INSTINCT_INGEST_TOKEN_FILE`. The worker sends one JSON envelope per HTTP `POST` with `Authorization: Bearer …` and a stable `Idempotency-Key`. It refuses redirects. The receiver must durably persist the event, deduplicate the exact key, and return a 2xx **only after** acceptance. A duplicate can return 200/202 after confirming the original was accepted. A 409 or timeout is retried; the outbox row remains pending. The token must be scoped to this endpoint and rotated through the host's secret manager. Do not put it in an argument, environment variable, image, or log.

Message events use `event_type` (`message`, `message_updated`, `message_deleted`), `account_id`, `chat_jid`, `msg_id`, `sender_jid`, `timestamp`, `text_or_caption`, `from_me`, `observed_at`, `triage_eligible`, and `revision`. The message identity is `(account_id, chat_jid, msg_id)`; the idempotency key also includes a content revision so edits/deletions can be delivered. A `re_pair_needed` event contains only `account_id` and `observed_at`. A `worker_degraded` event adds a private `error_code` for storage, lock, or process failures; ingestion outages are visible through `/healthz` until delivery recovers. The receiver should route these to a private event stream with explicit retention and access controls, and apply deletion events to any retained message payload. `triage_eligible=false` marks silent initial backfill and deletions. The bridge does not decide which messages need attention or send a notification for every captured message; the downstream classifier and notification policy are separate. The classifier should use sender, timestamp, and context and avoid invented urgency.

The bridge intentionally has **no webhook receiver**. A webhook is best-effort upstream, and its secret would otherwise appear in wacli process arguments. Startup, reconnect/completed-backlog events, and a 30-second periodic scan recover locally persisted messages if an immediate prompt is dropped. The source SQLite connection uses `mode=ro`, without `immutable=1`, so it observes concurrent WAL writes. The bridge never opens `session.db` for message access.

## Provision and pair

Use one persistent worker on a host with an **encrypted** disk or volume. Mount the same private data root at `/data/instinct` across redeploys; it contains `store/session.db`, `store/wacli.db`, their live WAL/SHM sidecars, and `state/instinct.db` with its own sidecars. Give only service UID 10001 access. Make the data root, `store`, and `state` mode 0700; DB files and the token file must be 0600 or tighter. Do not put the volume on a shared agent workspace or copy the linked-device store into a second running worker. The compose example at `deploy/instinct/compose.yaml` uses an encrypted host bind mount, a single named container, read-only image filesystem, and one process per store. A normal Docker named volume is **not** assumed encrypted.

Before starting the worker, pair interactively on that host with upstream `wacli --store /data/instinct/store auth` (or `auth --phone` in a controlled terminal). Keep terminal capture and general logging disabled during pairing. Do not record QR payloads, phone codes, message contents, or session keys in tickets, chat, git, or build artifacts. `sync` never displays a QR. If the store is not paired, health reports `pairing_required`.

From the paired account, inspect the target group with `wacli --store ... --read-only --json groups list`, `groups info --jid <candidate>`, and `groups participants list --jid <candidate>`. Check the group identity and a fresh participant snapshot, then have the account owner confirm it. Persist the **JID**, not the display name, in `INSTINCT_CHAT_JIDS`; only `@g.us` group JIDs are accepted. Do not guess or publish a real JID in this repository. The allowlist prevents other chats from entering the outbox. Own messages are skipped.

Set `INSTINCT_ACCOUNT_ID` to a stable opaque ID, `INSTINCT_STORE_DIR`, `INSTINCT_STATE_DIR`, `INSTINCT_CHAT_JIDS`, `INSTINCT_INGEST_URL`, and `INSTINCT_INGEST_TOKEN_FILE`. The store and state directories must be siblings named `store` and `state`. Optional `INSTINCT_SCAN_INTERVAL` defaults to 30s. Initial backfill is the latest 100 allowlisted messages and is marked silent; source cursor moves to the latest local row. The bounded lookback scans the last 2,000 row IDs on each pass to find in-place edits; full tombstone and purge-ledger sets are reconciled **only for already captured identities**. A replaced database is detected by file identity and cursor anchor, triggering a bounded silent rescan. Missing source rows are **never** interpreted as deletion. Changing the allowlist removes pending payloads for removed chats before delivery. Set `INSTINCT_MAX_DB_SIZE`, `INSTINCT_MAX_MESSAGES`, and `INSTINCT_MAX_STATE_DB_BYTES` to match your storage budget; defaults are 2GB, 250,000, and 512 MiB. Media downloads are disabled.

The example compose file requires `INSTINCT_ENCRYPTED_DATA_DIR`, `INSTINCT_INGEST_TOKEN_PATH`, `INSTINCT_ACCOUNT_ID`, `INSTINCT_CHAT_JIDS`, and `INSTINCT_INGEST_URL` in an operator-private environment file. Start with `docker compose -f deploy/instinct/compose.yaml up -d --build` only after the endpoint, encrypted volume, and JID are verified. Do not scale this service beyond one replica.

## Health and repair

The worker exposes `/healthz` on loopback port 8080. In the sample container, inspect it with `docker exec wacli-instinct wget -qO- http://127.0.0.1:8080/healthz`; the container health status also turns unhealthy on non-`connected` states. The JSON shows connection state, `last_successful_sync` (backlog completion), `last_reconciliation`, store bytes, pending outbox count, restart count, and an error code. It contains no JIDs, message text, or credentials. A quiet group may leave `last_successful_sync` unchanged while the connection remains healthy; this alone is not a reason to restart. Monitor both the health endpoint and durable ingest acknowledgements.

States distinguish `connected`, `catching_up`, `disconnected`, `pairing_required`, `re_pair_needed`, `degraded_ingest`, `degraded_disk`, `degraded_lock`, `degraded_store`, and `degraded_process`. A local or adapter DB cap or disk error needs space/retention repair; a lock conflict means another worker or wacli command is active; corruption needs an offline verified restore; ingest outage needs endpoint repair and outbox draining. If health shows `migration_required`, stop the bridge, run the pinned `wacli --store ... sync --once` under controlled supervision to let upstream migrate its schema, then restart the bridge. Check the store backup first and do not run another follow worker concurrently. If initialization fails before `/healthz` can bind, container stderr reports only a sanitized `degraded_lock`, `degraded_disk`, or `degraded_store` code. Transient failures restart with exponential backoff capped at one minute; ingest retries use the same capped backoff. A `logged_out` event or persisted revocation marker enters `re_pair_needed` even when upstream exits zero and stops automatic restarts. The worker persists a private repair event to its outbox. Re-pair only through a controlled interactive `wacli auth` flow, then restart the worker and verify health plus reconciliation. Keep the old local mirror until policy permits deletion.

If a previously observed `wacli.db` disappears, health reports `degraded_store` with `source_missing`. Check the encrypted volume mount before restarting or restoring. A fresh worker can wait for its first source DB during initial pairing, but an already captured store must remain mounted.

## Backup, retention, and deletion

Stop the worker before backup. `wacli-instinct backup ABS_DATA_ROOT ABS_SNAPSHOT_DIR` takes exclusive state and wacli store locks, then uses SQLite's online backup API for all three databases into a new 0700 directory on a **separately encrypted** backup mount. It includes the revocation marker. SQLite backup incorporates committed WAL contents; the snapshot does not need live WAL/SHM files. A running worker or standalone wacli process makes backup fail. Verify an offline restore into a **new absent** data root with `wacli-instinct restore ABS_SNAPSHOT_DIR ABS_NEW_DATA_ROOT`, then start exactly one replacement worker. Restore refuses an existing target and integrity-checks each DB. Never clone a linked-device identity into parallel deployments; retire the old worker first. Keep `store` and `state` together so cursor/outbox and source are coherent.

Choose an encrypted-volume key and backup key in the host's existing secret manager. Rotate them through the storage provider's supported re-encryption or offline snapshot/restore procedure; do not export `session.db` as a token. Keep backups only for an operator-approved retention window (for example 30 days) and enforce deletion at the storage provider. Accepted outbox audit rows older than 30 days are pruned automatically; accepted payload bytes are removed immediately, while `seen` identities are retained to preserve deduplication. The adapter DB has a hard size threshold and reports `state_cap_reached` before accepting more source rows. At that point, drain the outbox and increase the encrypted volume/threshold or perform an offline, reviewed maintenance migration; do not delete `seen` rows in place, since that can replay old messages as new. This fork retains local messages until explicit upstream cleanup or a storage cap stops capture; it does not silently delete target-group history. Approve a message retention budget before production, check pending outbox delivery before cleanup, and confirm the chosen upstream cleanup command's exact scope. On decommission, stop the worker, remove the linked device from the phone, delete the encrypted volume and backups, revoke the ingest token, and remove the allowlist configuration.

## Reliability boundary

After a WhatsApp message has been successfully persisted in the local `wacli.db`, the bridge transactionally records its event and cursor in its own WAL database. It advances the **local scan cursor** after durable outbox insertion; the row remains pending until a durable HTTP 2xx, then the private payload bytes are removed from the accepted audit row. A newer edit/deletion supersedes an older undelivered payload for the same identity. The receiver's idempotency key makes retries safe. This does not guarantee WhatsApp Web replays all missed phone/network history, and an edit outside the bounded lookback can be missed unless it has a tombstone/purge record. Validate end-to-end behavior with a paired account and one controlled test message before enabling alerts.
